# CP21 — сравнительные замеры CP20 и CP21

Дата: 5 ноября 2026. Обе версии измерялись **одними и теми же скриптами, последовательно, на одной машине**: Chromium 153.0.8010.12 (headless), Playwright 1.63, мобильная эмуляция 390×844. Замедление CPU в 4 раза (`Emulation.setCPUThrottlingRate`) — там, где указано «4×». Разброс между повторами — ±20–30 %; различия меньше этого **не считаются** улучшением или ухудшением.

Исходные данные: `verification/results/` (`swipeperf.jsonl`, `perf_CP20.json`, `perf_CP21.json`, `catswipe.jsonl`, `recalc.txt`).

## 1. Свайп статистики и истории: холодный, тёплый и повторный

Сценарии: **холодный** — свайп через 100 мс после открытия экрана (соседние категории ещё не подготовлены); **тёплый** — через 2,5 с; **повторный** — два свайпа подряд с интервалом 150 мс. История: 0, 300, 3 000 событий. 4×.

| Показатель | CP20 | CP21 |
|---|---|---|
| Переключение во всех холодных и тёплых сценариях | да (12/12) | да (12/12) |
| Два свайпа подряд → два переключения | **нет** (6 из 6 прогонов — одно) | **да** (6/6) |
| Длинные задачи (> 50 мс) во время видимого движения — холодный/тёплый | 0 | 0 |
| Пропуски кадров (> 34 мс) во время движения — холодный/тёплый | 0 | 0–1 (одно значение 50 мс в холодном сценарии, 300 событий) |
| Повторный свайп: пропуски кадров | 0 (второго перехода нет) | 0–1 кадр 50–67 мс в 3 из 6 прогонов — построение следующей категории во время «протяжки» (см. CP21_PENDING) |
| Первая реакция после фиксации жеста, тёплый (6 значений) | 104–117 мс (и одно 184 мс) | 102–114 мс |
| Первая реакция, холодный (6 значений) | 114–163 мс | 113–192 мс |

«Первая реакция» — время от момента, когда палец сместился на 12 px, до первого кадра с движением содержимого. Значение включает задержку доставки событий через CDP при 4× замедлении: в тёплом сценарии и без какой-либо работы приложения оно около 100 мс. Поэтому сравнивается **разница холодный − тёплый**. Она в обеих версиях от 0 до ~80 мс (синхронная сборка соседней категории). Устойчивого различия CP20/CP21 нет. Это сознательный остаток: см. CP21_PENDING.

Плавность самого движения (перемещение за кадр ≈ скорости пальца, отсутствие скачков, продолжение со скоростью пальца) — без изменений относительно CP20. Подтверждено регрессионными проверками «content follows finger without jumps» и «finger catches the settling animation without a jump» (раздел 3 CP21_TEST_REPORT).

### Отдельный замер `perf.js` (3 000 событий, 4×, кадры после отпускания)

| | CP20 | CP21 |
|---|---|---|
| Кадры перетаскивания с движением содержимого | 7–8 из 12–13 | 8 из 12–13 |
| Наибольший сдвиг за кадр | 27,5 px | 27,5 px |
| Паузы > 34 мс после завершения перехода (содержимое неподвижно) | 50–117 мс в 3 из 4 сценариев | **нет ни в одном** |

Последнее улучшение — следствие принятия готового слоя (без повторной отрисовки при завершении) и подготовки в простое с учётом бюджета кадра.

## 6. Оценка дополнительных вариантов оптимизации (раздел 7 задания)

| Вариант | Причина / ожидаемая польза | Стоимость, риск | Решение и результат |
|---|---|---|---|
| Повторное использование готового фрагмента (принятие подготовленного слоя) | Завершение свайпа без повторной отрисовки; нужно для «протяжки» | Низкая; риск устаревания слоя закрыт сбросом кеша при каждой отрисовке | **Внедрено**: паузы после перехода исчезли (п. 1) |
| Подготовка соседних вкладок | Уже есть в CP20 | — | **Сохранено**, улучшено: бюджет кадра, повтор вместо отмены, приоритет направления |
| Отложенное выполнение некритичных вычислений | Сборка в простое | Низкая | **Внедрено** (бюджет ≥ 12 мс) |
| Неполная отрисовка длинных списков | История в слое — только видимые строки | Низкая | **Внедрено** для слоя истории (24–80 строк) |
| Сокращение обходов DOM / локальное обновление | Профилирование не выявило узких мест: обновление карточек уже локальное (`refreshCard`) | — | Не требуется |
| Отказ от анимаций свойств, вызывающих перерасчёт геометрии | Анимируются только `transform`/`opacity`; заливка переключателей — цвет | — | Не требуется |
| Удешевление частых обработчиков | `touchmove` пишет только координаты, отрисовка объединяется в `requestAnimationFrame` | — | Не требуется |
| Устранение полного пересчёта стилей при смене каталога (D-01 из CP20) | ~50 мс при 4× | Высокая: перестройка переменных темы | **Не внедрено** (CP21_PENDING) |
